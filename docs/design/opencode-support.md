# Codex 与 OpenCode 双来源支持

## 状态

双来源实现已随 v1.0.7 发布。2026-10-21，用户确认本机 OpenCode CLI 可触发真实提醒；OpenChamber 2.5.0 改用本机 OpenCode V2.1.1 并重载后，用户也确认收到真实主会话完成提醒。

OpenCode 支持范围扩展至 2.x 稳定版（>= 2.1.1 且 < 3.0.0），允许后续 2.x 次版本与补丁，拒绝预发布和格式非法版本。已完成官方 npm 发布包 2.1.1 与 2.1.3 的 SHA-512 校验与静态源码比对，确认插件与核心事件定义兼容；但 2.1.3 的真实用户会话尚未完成端到端实测验收。依然不兼容 V1、不支持 3.x 或其他范围外版本，不覆盖远程服务器、SSH 或容器。下方保留历史阶段记录，最新实机与版本核验见文末。

## 产品边界

- CueDex 是编码助手的注意力路由器，首批来源为 Codex、OpenCode。
- 来源是应用，不是模型或模型供应商。OpenCode 使用 OpenAI 模型时，仍选择 OpenCode 配置。
- 首版仅接入本机运行的工具，不覆盖远程服务器、SSH 或容器实例。
- 只提醒主会话一轮回复成功结束，不提醒子会话完成、等待授权、等待输入、失败或主动取消。
- 不做聊天客户端、会话管理器、hook 编辑器或通用自动化平台。
- 不保留提示词或回复正文，不通过对话内容猜测事件来源或完成状态。

领域术语以根目录 `CONTEXT.md` 为准。

## 两套独立配置

Codex 与 OpenCode 的来源配置使用同一种结构，各自保存独立的配置值；不是来源配置之间的默认值继承、覆盖层或自动同步。用户在首轮实现后进一步简化设置：光效固定 100% 强度、持续 3 秒，不再提供来源或通用配置入口；提示音与语音不再提供应用内音量设置。

按来源独立的项目：

- 光效开关、动画、颜色。
- 提示音开关、音色、自定义音频。
- 语音开关、系统语音或录音模式、声音、文案。

全局共用的项目：

- 界面语言、开机启动、暂停提醒、免打扰时间。

光效固定参数对两个来源及其预览都生效。保留呼吸/交替闪烁动画与边缘渐变，不额外衰减用户所选颜色的强度。

提示音、自定义音频、录音语音及系统语音均跟随系统音量；CueDex 不再保存或应用额外的音量衰减，不修改系统输出音量或静音状态。

用户自行决定是否通过不同颜色、声音或语音辨认来源。允许两套配置完全相同；不新增来源浮层或文字标签，不强制使用不同效果。

### 初始值与迁移

- 旧配置中的来源选项迁移为 Codex 配置，不重置颜色、音色、语音文案或开关。
- 旧配置中的语言、暂停与免打扰状态继续作为全局设置。
- 旧单来源、双来源草稿和通用配置中的光效强度、持续时间全部忽略；新配置不再写入这两个字段。无需迁移其数值，统一使用 100%、3 秒，不影响颜色、动画或其他设置。
- 旧提示音和语音音量字段不再使用，也不写入新配置；不把旧音量写入系统设置。
- OpenCode 使用初始默认值，不自动复制 Codex 的自定义配置。
- OpenCode 默认系统语音文案使用正确的来源名称；用户自定义文案不自动改写。
- 默认颜色或声音可以相同，不为区分来源擅自创建不同默认值。
- 停用接入不删除该来源的配置，重新启用后继续使用。

## 设置与菜单栏

### 布局：来源优先

设置窗口采用三个主分类：**通用 / 提醒 / 关于**，保留 macOS 原生分组表单风格。

- **通用**：语言、两种来源的接入状态与启用/停用操作、开机启动、全局暂停及免打扰；不再显示光效强度、持续时间。
- **提醒**：左侧选择 Codex 或 OpenCode，右侧切换光效、声音两个子页；语音仍位于声音页。来源光效页不显示强度、持续时间，也不再提示前往「通用」调整；声音页不显示音量滑杆，并说明跟随系统音量。
- 用户选择保留光效/声音 tab：切换控件收窄至 200 pt 并居中，顶部留白 16 pt，下方额外留白 12 pt，与表单内部分组间距一起区分导航和设置。三个效果开关统一显示「是否启用」（英文为 Enabled），不改变开关含义或来源切换逻辑。
- **关于**：更新产品说明，不再将 CueDex 描述为 Codex 专用工具。

切换来源只改变正在编辑和预览的配置，不启用接入、不触发提醒，也不改变真实事件的路由。尚未接入的来源仍可编辑、预览配置。

两个来源复用相同的配置控件，不复制两份容易产生功能差异的设置界面。来源切换时，光效与声音子页使用一致的编辑对象。

### 测试入口

- 设置页测试当前编辑来源的对应效果。
- 菜单栏的“测试提醒”展开为“测试 Codex / 测试 OpenCode”，不隐式使用上次编辑的来源。
- 测试仅是本地效果预览，不代表已成功收到 Codex 或 OpenCode 事件。
- 预览不能使接入状态变为已验证，也不计入最近收到的真实完成事件。
- 正在播放提醒或预览时，测试按钮暂不可用，避免手动测试打断当前播放；切换来源时保留当前光效/声音子页，便于比较两套配置。

### 全局接入与状态

- 用户主动启用后，OpenCode 接入默认覆盖所有本地项目，不要求逐项目安装。
- 两种来源分别启用、停用、展示状态与安装说明，暂停和免打扰仍全局控制。
- 修改前说明接入将写入的位置及必要的加载步骤；只管理 CueDex 自己的配置项，保留其他工具或插件的配置。
- 配置写入成功显示“已配置”，不直接显示“已连接”。需要重新加载时明确提示，不擅自重启用户的工具或服务。
- “最近收到完成事件”与“已配置”分开展示。历史上收到过事件也不代表当前仍然连通。
- 未配置、不支持的版本、安装/加载异常应有明确说明，不能伪装为正常接入。

## 真实提醒的路由与排队

1. 接入适配器识别事件来源，筛选有效的主会话回复完成事件。
2. 保留来源与事件身份，先过滤重复、过期、暂停、免打扰或已停用来源的事件，再进入队列。
3. 当前提醒播放结束后，再播放下一条，不因另一来源完成而打断当前提醒。
4. 每种来源尚未播放的提醒最多保留一条；同来源新完成事件替换其旧的待播提醒。
5. 相同完成事件的重复投递属于去重问题，不应被当作新的完成事件反复替换或播放。
6. 沿用现有 60 秒事件时效；播放前再次检查，过期提醒丢弃。
7. 暂停或进入免打扰时停止当前提醒并清空队列；期间事件直接丢弃，恢复后不补报。
8. 停用某个来源仅停止、清理该来源的提醒，不影响另一个来源，也不清除配置。

播放时必须使用事件所属来源的配置，而不是设置窗口当前选中的来源。多个效果可同时播放；队列推进需要协调启用效果的结束，不能只依赖光效时长而截断声音或语音。

## 接入实现依据

本节记录实现约束与已核实事实，不把建议的数据结构当作已存在的接口。

### Codex：保留已有安装与升级能力

当前 `CodexIntegrationInstaller` 管理 `hooks.json` 的 `Stop` handler，兼顾旧版 notifier 迁移。helper 筛选事件后写入空标记；`CodexEventMonitor` 回调没有参数，同次扫描还会将多个标记合并。

双来源实现必须在投递给提醒路由器之前保留来源和事件身份，不能让 OpenCode 直接复用无来源的空标记。Codex 原有的配置保留、备份、卸载和旧版迁移能力不能回归。

当前去重仅使用一个最近 turn ID；需要覆盖跨会话交错与重复投递，而不是仅在现有全局值前加来源名称。现有 `Stop` 过滤对“成功回复结束”的保证也需要按 Codex 实际契约核对，不能因为消息非空就推断所有终止都是成功。

实现中已将 helper 升级为带来源的元数据事件，并以 session + turn 的原子声明去重，覆盖交错和并发的重复投递；同时修正 `plutil` 字段缺失时将标准输出错误文字误判为回复的旧问题。

**Codex 兼容性边界：** 上游当前源码的 `run_turn_stop_hooks` 在没有模型 follow-up 时运行，主子会话分别分派 Stop/SubagentStop，但其他 Stop hook 仍可以阻止结束、要求继续执行。因此现有 Stop 接入不等于所有 hook 处理后的最终成功确认。本次保留 Codex 的既有接入机制，不能宣称这个边界已被消除；上游 main 源码也不等于用户已安装版本的契约。该场景仍须在真实工具验收中检查。

相关位置：

- `CueDex/Services/CodexIntegrationInstaller.swift`
- `CueDex/Services/CueEventMonitor.swift`（由原 Codex 专用监控器演进）
- `CueDex/Stores/AppModel.swift`

### OpenCode V2.1.1：成功事件与主会话过滤

已从官方发布、版本匹配的 npm 包源码核实：

- 成功事件为 `session.execution.succeeded`，通过 `data.sessionID` 标识会话；成功由事件类型表达，没有额外的 `outcome` 字段。
- 原生事件包含 `id`、`created` 和 durable 元数据；事件自身的 `location` 可选。
- `session.execution.failed`、`session.execution.interrupted` 不触发首版提醒。
- 查询会话元数据后检查 `parentID`，只接受主会话；查询失败时跳过，不猜测它是主会话。
- 会话所属位置来自会话元数据，不能使用插件实例的 `ctx.location` 代替。
- Promise 插件的 `ctx.session.get` 直接返回 `Session.Info`；原始 HTTP 的 `data` 包装不能照搬到插件调用。
- `Session.Message.Idle` 是执行事件的投影，不是原生事件类型名称。

**成功执行不必然代表产生了一轮回复。** 手动压缩上下文或其他控制操作也可能成功结束，因此必须结合本轮主回复步骤的证据筛选，不能把成功事件直接等同于用户需要的回复完成。

版本匹配的源码进一步确认：主回复路径会发出 `session.step.started`，辅助标题生成、瞬时 generate 和纯压缩/控制操作本身不发出这种主回复步骤事件。但重试前也可能发布 started，所以仅观察到 started 仍不足以证明该步骤成功结束。

基于源码推导、仍待运行时验证的保守判据是：

- 连续观察到同一会话的 `session.execution.started`，建立本轮边界。
- 观察到最新主回复步骤的 started，以及后续匹配的 `session.step.ended`；有新的 started 或失败证据时使旧的完成证据失效。
- 随后收到本轮 `session.execution.succeeded`，并确认会话没有 `parentID`，才允许提醒。
- 按会话和递增的 `durable.seq` 关联边界与步骤；事件没有显式 execution ID，重试也可能复用 `assistantMessageID`，不能仅靠该消息 ID 关联执行轮次。
- 步骤 `finish` 只是判据的元数据；当前保守实现仅接受最终匹配步骤的 `stop` 或 `length`，单个 `tool-calls` 步骤结束不能独立触发整轮完成提醒。

这些是基于源码推导的接入判据，不是 OpenCode 内建的通知保证，仍须受控验证。该方案不需要读取对话正文，但也不能据此宣称回复一定包含非空的可见文字。

**已确认的边界行为：** 若插件在一轮执行中途加载，或连接中断导致错过其 `execution.started`，不为这一轮提醒，清空不完整关联状态并等待下一轮完整观察到的执行。该策略宁可漏掉一次完成，也不凭不完整证据误报；它不等同于断线后的历史补报。

插件实例按 location 加载，但其公开事件订阅可能收到全服务事件。因此多个项目中加载的实例可能重复投递同一事件，CueDex 接收侧必须按来源和稳定事件身份集中去重，而不是只按 session ID 去重。

事件流只提供实时数据，不保证断线重放或客户端自动重连。durable 元数据不等于 SSE 支持历史回放。发生连接缺口时不凭空补造完成提醒，也不将状态未知显示为健康。

### 本地桥接与数据最小化

优先保留现有本地、事件驱动的接收方式，分别适配两种来源，共用路由、队列和效果服务。具体桥接协议须在只读契约核查与最小验证后确定。

归一化事件只携带路由与去重必需的元数据，例如来源、稳定事件标识、会话标识、发生时间及完成类型。不转发、保存完整对话、模型输出、工具参数、任意 metadata 或错误正文。

如果上游订阅流包含正文，桥接必须过滤，不能把原始事件整体写入文件或诊断日志；也不能把“只保存元数据”宣传为“接入完全不会接触正文”。

## 实现影响与回归要求

- **偏好模型与持久化**：拆分全局设置和按来源保存的同构配置；迁移幂等、旧配置不丢失，未知字段或枚举维持兼容策略。
- **自定义音频**：一边替换或删除音频不能使另一边配置失效；共享文件或独立副本的生命周期必须明确，不能沿用单配置的无条件删除逻辑。
- **提醒编排**：集中处理来源路由、去重、时效、队列、暂停和免打扰，避免两套来源各自抢占同一播放服务。
- **界面与本地化**：共享配置视图；更新通用、提醒、关于、菜单测试和默认语音，中英文同步。
- **安装器**：分别管理两个来源，保留用户已有配置；不以预览成功冒充端到端接入成功。

至少覆盖以下验收场景：

- 旧用户升级后 Codex 的颜色、音色、语音、自定义文件及全局行为均保留；OpenCode 来源配置使用默认值，两个来源的光效均固定 100% 强度、3 秒，声音跟随系统音量。
- 修改、预览、停用某来源不串改另一来源的配置或接入状态。
- 设置中选中 OpenCode 时，Codex 真实事件仍播放 Codex 配置，反之亦然。
- 同一会话后续回复可再次提醒；重复事件、跨会话交错事件、多插件实例重复投递不会重复提醒。
- 两个来源同时完成依次播放，同来源待播只保留最新一条；声音和语音不被下一条提前截断。
- 过期、暂停、免打扰、停用来源的事件按规则丢弃，恢复后无积压补报。
- OpenCode 子会话、失败、中断、自动重试中间态、标题生成、压缩或无回复控制操作不误触发。
- 事件流连接缺口、会话查询失败、版本不支持时保守处理，状态说明真实；中途加载或缺少执行起点时不提醒当前轮次。
- 安装与卸载不破坏已有 Codex hooks、OpenCode 插件或其他用户配置。

落地时运行现有完整 `xcodebuild ... test`，并以受控的本机主会话完成事件分别验证两个来源；单靠设置页或菜单栏预览不算接入验收。
